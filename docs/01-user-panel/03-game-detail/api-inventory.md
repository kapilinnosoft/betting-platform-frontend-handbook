# Game Detail (API inventory)

This table uses backend path and method as the common reference. Aliases identify the hook names found in source; they do not imply identical frontend types or UI behavior.

| Capability | Method and path | Source aliases / request details | Response / use |
|---|---|---|---|
| Catalogue | `GET /catalogue/:eventId` | `getCatalogueByEventId` accepts optional `sport`, `search`, `inplay`, and `matchTime`; `getMatcheDetails` takes `sportName` and `eventId` but builds the URL from `eventId` (`src/apis/catalogueApi.ts:44-60 (getCatalogueByEventId)`, `src/store/api/sportsApi.ts:229-235 (getMatcheDetails)`). | Catalogue contains event, markets, fancy markets, premium markets, status and in-play state; market page also reads `betConfig` (`src/pages/GameDetails/Hooks/useCatalogData.ts:35-44 (useCatalogData)`, `src/pages/Markets/index.tsx:32-35 (Markets)`). |
| Bet placement | `POST /bet/place` | Aliases: `placeBet`, `betPlace`. Common fields include event, market, selection, runner, stake, rate, bet side and odds-change preference. Typed field details vary; the team-provided backend contract and a field comparison are in [bet placement › backend contract](bet-placement-flow.md#backend-contract-team-provided-2026-11-19-q-22) (`src/store/api/betPlaceApi.ts:11-20 (placeBet)`, `src/store/api/betApi.ts:213-231 (betPlace)`). | Mutation response is used for success/error feedback; bet mutation invalidates book/exposure cache tags (`src/store/api/betPlaceApi.ts:6-20 (placeBet)`, `src/store/api/betApi.ts:213-231 (betPlace)`). |
| Bookset/exposure | `GET /exposure/bookset/calculation` | Aliases: `getBooksetCalc`, `getBookset`. Both use `eventId` and add `t=Date.now()` (`src/store/api/booksetApi.ts:34-43 (getBooksetCalc)`, `src/store/api/betApi.ts:207-212 (getBookset)`). | Array of market records with `marketExternalId` and selection `exposure`; matched by market and selection in the UI (`src/store/api/booksetApi.ts:3-20 (ExposureResponse)`, `src/hooks/useMarketExposureData.ts:17-35 (useMarketExposureData)`). |
| Session/fancy P&L | `GET /exposure/profit-loss` | Aliases: `getFancyProfitLoss`, `getSessionPL`. Query fields include `eventId` and `selectionId`; one call also includes `marketId` (`src/store/api/booksetApi.ts:22-50 (getFancyProfitLoss)`, `src/store/api/betApi.ts:270-284 (getSessionPL)`). | P&L array consumed by book/session UI. Full business calculation is not established by this page. |
| Stake settings | `GET /stakeset`, `PUT /stakeset` | Query aliases: `getStakeSet`, `getStakes`; mutation aliases: `updateStakeSet`, `updateStakes`. ## Related media APIs

`GET events/scorecard/:eventId` supplies `scorecardUrl` and `liveTvUrl`; raw-scorecard paths are covered in [Modules 5–7](../05-scorecard-live-tv/api-inventory.md). Their full contracts are intentionally not duplicated here (`src/store/api/eventsApi.ts:317-323 (getScorecard)`). Bet-history endpoint definitions and consumers are listed in the [central API registry](../../../inventory/api-inventory.md); their report contract is in [Module 4 › S3](../04-reports/api-inventory.md#s3-getbethistory).

All response shapes are source-derived, not verified against captured backend responses. Same path/method is evidence of a shared route, not proof that all payload fields and behavior are interchangeable.
